# RC22：约束范围修复

本次是 **4.3.0-rc.22** 的有界修复归档。**完整发布仍为NOT_READY，生产保持4.2.0，未激活RC22。** [RC21的十二题与方法实验](v43-rc21-verification.md)未重跑，失败及未知保持；本轮没有新增业务质量成绩。

## 修复与验证

- “查看导出逻辑”等检查动作不再因已有产物名词被识别为创建文件；源材料只读与另行交付文件分别保留。
- 明确禁止连接或下载到设备的要求传入建议守卫，不扩大成全面禁网。带限定词或无法分类的对象保留原约束，交由宿主核对，不截成所有设备禁令。
- 已知直接设备操作可被建议为跳过；通用执行器及效果不明的工具仍须核对范围，不被包装成只读工具。以上是有限语法和建议层检查，不替代真实授权及执行验证。

冻结的134文件候选通过 **7组整合检查**，专项 **440项、0跳过**。新增约束专项18项通过；其中原16项按相同修正后断言比较，RC21为4通过、12失败。独立审查额外10个反例，RC21为6通过，RC22为10通过；结论是 **ACCEPT_KNOWN_SCOPE**，不是新保留集、全面自然语言覆盖或上线批准。简单题无扫描失败不在本补丁范围内。

公共副本一次验证：**基础41/41、专项440/440、demo通过**，均无跳过。设备建议模块按RC21→RC22差异块应用，保留公共便携目录适配；路径、宿主规则、示例和许可保持。两段已消费题在公共测试中替换为原创等价短句并移除题号，触发语法和全部断言保留；改写在测试前固定，本次一次通过，没有据结果改写重试。公共测试因此不与私有冻结字节完全相同，两套440项不相加。远端CI须按未来具体提交另查。

## 设施入口校准的边界

另有一次固定校准：**9次MCP请求、0模型调用、0业务重跑或重试**。影子接口的route省略档、compact及full响应，与**冻结RC21的标准MCP入口**在规定排除字段后相同。记录里的`production`只是该测试服务的标签，**不是用户当前4.2.0服务，也不是RC22实际生效**。

search仅核验影子接口输出和已读处理器格式，标准入口直接对照仍为 **UNKNOWN**。固定简单输入的一致不证明复杂请求、业务时延、超时原因或质量收益；旧六次超时与零方法暴露未改写。两个自建服务已关闭。
