# RC21：方法范围修复与验证边界

本记录对应 **4.3.0-rc.21** 可移植候选。仅增量同步已冻结源码和回归测试，保留公共仓库的隔离目录、示例配置与许可。**完整发布仍为 NOT_READY，生产保持4.2.0。** [RC19](v43-rc19-verification.md)及更早记录的失败、未知和质量退化均保留。

## 已验证的机制

- 方法建议使用独立的作用范围：同一主题的相邻逗号分句可以衔接；句号、被排除或截断的内容及不同对象形成边界，不改变原检索分句。
- 当前明确禁用某方法会阻止隐式再次推荐；经过来源过滤的后续明确改口按顺序处理。引用、示例和未来要求不因此成为当前授权。
- 在已有正反理由或可逆验证计划需求时，可建议对应方法；概念介绍不自动等同要求应用。原生足够及快速路径仍可不提供方法卡。
- 实验设计识别要求设计、分配、评审或真实决策动作；固定种子、样本量和重复次数本身不构成设计需求。
- RC21增加“选定”这一明确选择动作，未采用会扩大误匹配的裸“决定”词规则。

方法仍是可跳过的咨询卡，最多两张，不自行执行工具或要求用户完成固定问卷。

独立审查结论为 **ACCEPT_KNOWN_SCOPE**，仅认可本次已检查机制，不是质量或上线批准。两类既有决策表达仍漏识别：以“决定”为动作选择方案，以及决定预算如何分配。实验平台网页类请求仍有既有实验设计谓词误匹配。这些局限未被改写成通过，前轮失败审查也保留。

## 方法卡实验与新保留验收

RC20沿用原方法题与评分条件，正式route和阶段search开/关都为 **0/0**，操纵未成立，业务执行 **0次**；预定六次没有运行。

RC21对同一原题的**零模型接口成对探针**中，route和search均为 **1/0**。剔除事前规定的标识、版本与性能字段后，其余响应相同；去除方法部分后格式化上下文也相同，故仅这一次接口开关操纵成立，不能推断正式模型实际收到方法卡或产物受益。

正式六次模型执行均自行传入`nativeSufficient:true`，实际方法暴露为 **0**，已按90秒限额结束。五次没有生成指定文件；一次写入两个文件，但模型未完成读回或最终答复。最终独立盲评待结算，**此记录暂不报告分数**；接口1/0不冒充这六次模型的有效方法暴露。

另有新十二题保留验收，**78次纯路由调用已完成，进程错误为0**，正式判读尚待结算。执行完成不等于验收通过，也不把已消费题的改善冒充新保留成绩。
