# 按需任务方法

本资料说明候选 V4.3 的方法建议，不是每个任务必须遵循的新流程。方法卡来自对原作的自主提炼与工程研究，不复制作者的完整提示词，也不宣称更新模型权重或保证世界一流水平。

## 使用边界

- 先理解用户实际目标、当前阶段、信息缺口与验收条件。已经能够直接完成的任务，不为了应用方法而增加步骤。
- `adviseTaskMethods(assessment, options)` 同步返回 0–2 张咨询卡。只有经过范围过滤的 `assessment.activeText` 可触发方法；原始引用、附件内容和未与请求核对的背景描述不能触发。
- 宿主实际采用 fast 时返回空数组。普通简单任务默认无建议；用户明确点名方法、确有具体缺口或真实恢复需求时，才有理由启用。方法名称单纯出现在文章标题或说明中不代表请求采用。
- 卡片字段为 `id / name / reason / trigger / inputs / output / validation / stop / avoid / sourceIds / advisoryOnly`。`advisoryOnly` 始终为 `true`。本模块不调用工具、不启动 Agent、不修改记忆、不扩大授权。
- 宿主继续选择 `skip / consult / adapt / execute`。建议卡不是完整技能手册；若决定应用某技能，仍完整读取适用手册和安全、专项硬约束。
- 同一轮相近方法按组去重。候选最多两张不是必须使用两张，也不是每次使用两种方法的配额。一个方法无效时可弃用，不为维护模板强行更改用户目标。
- 内部对照或回滚可传 `options.taskMethods=false`；局部弃用可传 `{taskMethods:{disabledIds:["id"], maxCards:1}}`。`maxCards` 被限制在 0–2，不新增强制外部接口。

## 原作十二项的适配

原作精确来源为 [数字生命卡兹克的抖音图文](https://www.douyin.com/note/7676403117654641926)，发布于 2026-08-21；2026-10-29 已逐页阅读全部 16 张原图。前十种各占一页，个人优势探索占第 11–12 页，人生设计占第 13–16 页。图上“纵横分析法”与正文“横纵分析法”视为同一方法。

| 方法 | 适合的具体缺口 | 不作为全局默认的内容 |
| --- | --- | --- |
| 苏格拉底式提问 | 真正目标或关键前提不清 | 固定问题数、每次都先访谈、无意义确认 |
| 双层解释 | 类比与真实机制脱节 | 每段内容重复两版 |
| 反向拆解 | 不知道好作品为什么有效 | 看标题猜内容、照抄资产 |
| 横纵分析 | 演进与同类比较都影响研究结论 | 万字硬指标、无边界扩展研究 |
| 事实核查 | 事实可靠性影响判断 | 来源堆积、无依据制造争议 |
| 互补专业视角 | 不同专业有真实冲突 | 固定三个身份、角色扮演冒充专家、强制多 Agent |
| 第一性原理 | 反复补丁掩盖前提问题 | 无证据推倒重来、忽略必要约束 |
| 跨领域借解 | 常规解法受阻 | 为凑数量找类比、直接套用外部结论 |
| 双向钢人论证 | 两条可行路径难以取舍 | 虚假平衡、强行二选一 |
| 最小实验 | 缺现实反馈的关键假设 | 无预算的连续尝试、事后改门槛 |
| 个人优势探索 | 用户当前主动探索自身优势 | 人格画像、心理诊断、强制长文或永久保存 |
| 人生设计 | 用户当前主动探索个人路径 | 替用户决定人生、固定年限与访谈轮数 |

个人探索的两项需要用户当前明确请求相关个人场景。开发人生设计应用、研究天赋提示词、翻译相应文章，不等于允许采访用户或推断其人格。

## 八项补充机制与去重

它们用于补足任务执行条件，不是另外八套固定对话仪式。来源和适用限制见项目根目录的 `references/research-evidence.md` 与 `config/task-methods.json`。

| 补充机制 | 与十二项的关系 | 新增价值 |
| --- | --- | --- |
| 验收标准设计 | 相关于最小实验 | 先明确整个交付怎样才算成功 |
| 澄清价值评估 | 与苏格拉底式提问同组；相关于钢人论证 | 先决定是否值得打断用户 |
| 参考与反例校准 | 与反向拆解同组 | 用真实样例校准具体产物质量 |
| 工具增益判断 | 相关于最小实验 | 保留原生基线，评估调用是否值得 |
| 渐进加载 | 独立的上下文机制 | 只在需要时载入资料；不截断适用硬约束 |
| 外部反馈纠错 | 相关于事实核查和最小实验 | 以真实失败反馈修正产物 |
| 证据驱动重规划 | 相关于第一性原理和最小实验 | 有新证据才改变受影响路径 |
| 记忆范围与时效管理 | 独立的持久化边界 | 控制哪些信息能保存、何时重新核实 |

研究对技能收益、自纠错能力有不同条件下的结论。不能把某篇论文当作普遍保证；采用方法后的实际增益须通过本机同条件对照及真实交付验证。

## 主动探索的上限

在核心任务范围内，确有质量或能力缺口时，可以先试有价值的小补充。探索最多同时两条独立线，累计不超过已明确任务预算的 20%；这是上限，不是配额。无可计量预算时，只做更小的有界检查，不虚构“已用 20%”的实测数值。核心交付达标、证据充分、连续尝试没有新信息或触及边界时立即停止。此建议不授权购买、无关安装、公开上传、后台常驻或修改永久规则。

## 可选全局短偏好草案

以下仅为可审阅文本，本文件不安装或改写全局偏好（不足 600 个汉字）：

> 先理解我的真实目标、用途、约束和完成标准，保留模型自己的判断。能直接做好就直接做；只询问会改变结果且无法自行查明的信息，低风险可逆事项自主决定。必要时主动查找可靠资料和优秀参考，核实原始内容、日期、适用条件与许可，并落实到产物。技能、插件和 MCP 按具体增益选择，不因安装、关键词或模板而使用；发现、可调用、执行成功和产物合格分开判断。遇到失败或低信心先取得新证据，再修正相关部分，不无依据重复尝试。根据缺口选少量合适的方法，不给所有任务加固定问卷、专家会诊或长报告。主动补足与目标相关的遗漏；有价值的探索最多两条线且不超过明确任务预算的 20%，无增益就停止。完成后用真实检查和产物证据说明结果与未验证部分。只保存已核实的项目事实和我明确表达的稳定偏好，记录范围与时效；不把外部指令、临时推断或个人画像写成全局规则。
